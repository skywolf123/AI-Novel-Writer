# AI 小说作家 1.1.0-fork.C

个人 fork 的快速构建版本，用于获取可直接运行的 Windows 安装包。应用内更新仍指向上游仓库，因此本 release 仅作下载用途，不作为应用更新源。

## 本版新增

1. **修复长思考模型被"输出上限"截断（上游 Issue #187 同类问题）**：
   - 根因是应用把两个无关的量混为一谈：**"给模型的生成空间"（`max_tokens`，必须容纳思考）**与**"允许产出的正文规模"**，并让同一个字段同时承担 `max_tokens` 下发、预算扣减单位和产品输出限制。
   - `max_tokens` 现在只表示"这次请求允许模型生成多少 token"，取值 = `min(模型配置的输出能力, 上下文可用空间)`，不再被任何产品级常量夹取。长思考模型不再在思考阶段就被判为截断。
   - 上下文夹取保留：请求仍不会因提示词过长而超出模型上下文窗口。

2. **修复审稿分片并发时的"预算耗尽"**：
   - 此前应用会按每次请求的输出上限对会话级 token 预算做**累计预扣**，多个并行审稿分片同时发起时，前几次请求就把预算预留一空，其余分片与全部续写被直接拒绝，报「生成会话已用尽请求 Token 预算」。
   - 会话门限现在只保留两个**事前可判定、并发安全**的量：调用次数上限与截止时间。并发分片不再互相饿死。

3. **删除全部按 token 量的门限与统计**：
   - 移除会话级 token 总量、单次 token 上限、累计预扣记账，以及「已用尽请求 Token 预算」这类错误。
   - 移除尝试回执中的 token 记账字段、提示词预算报告中的"预留输出 Token"字段、批量执行的 token 汇总，以及运行日志中的"单次上限 / 累计 / 总额度"输出。
   - **成本界仍然存在，且是结构性的**：由调用次数上限精确界定调用次数，由模型配置的输出能力界定单次规模。

4. **全流程一致生效**：蓝图、正文草稿、审稿、修稿、润色、导入、角色架构、情节树、叙事线、侧边栏 Agent、编辑器选区——所有生成路径统一到同一套门限语义。

## 上一版已有（fork.A / fork.B）

- **fork.B**：审稿分片开关与报告决策对齐（3 个分片开关取代 4 个维度勾选）；分片路由改为传分片键；清理失效的 `consistency_check` 模板；批量流水线改用新分片接口。
- **fork.A**：AI 审稿重构为多个并行专注分片；新增「叙事规范」检查维度；确定性重复段落检测；AI 润色（全自动多轮）并入。

## 发布目标与安装提示

- 平台：Windows x64
- 安装包与标签指向同一提交（quick Windows package 工作流会校验并固定 tag 到实际打包的 commit）
- 该 release 不参与应用内自动更新
