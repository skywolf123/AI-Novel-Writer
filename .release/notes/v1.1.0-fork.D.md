# AI 小说作家 1.1.0-fork.D

个人 fork 的快速构建版本，用于获取可直接运行的 Windows 安装包。应用内更新仍指向上游仓库，因此本 release 仅作下载用途，不作为应用更新源。

## 本版修复

1. **修复"合并修订稿后立即审稿/修稿被拒"**：
   - 审稿修复的修订稿合并进正文时，数据库会把草稿状态从 `draft` 置为 `revised`，但打开中的编辑器标签页仍保留陈旧的 `draftStatus`。
   - 随后立即执行 AI 审稿/修稿时，冻结源稿取到的是标签页里的陈旧状态，与数据库比对不符，被源稿守卫拒绝，报「源草稿在 AI 审稿期间已变化。审稿报告未保存…」——期间作者并没有手动改动正文。
   - 现在合并提交成功后，标签页的草稿状态会同步为 `revised`（包括提交等待期间出现新输入的情形），合并后无需重开草稿即可继续审稿/修稿。

## 上一版已有（fork.C）

- **修复长思考模型被"输出上限"截断**：`max_tokens` 改为取 `min(模型配置的输出能力, 上下文可用空间)`，不再被产品级常量夹取（上游 Issue #187 同类问题）。
- **修复审稿分片并发时的"预算耗尽"**：取消会话级 token 累计预扣，门限只保留调用次数与截止时间，并行分片不再互相饿死。
- **删除全部按 token 量的门限与统计**；成本界改为结构性（次数上限 × 模型声明能力），全流程（蓝图/正文/审稿/修稿/润色/导入/架构/情节树/叙事线/Agent/选区）一致生效。

## 更早版本

- **fork.B**：审稿分片开关与报告决策对齐；分片键路由；清理失效模板；批量流水线适配。
- **fork.A**：AI 审稿并行分片重构；新增「叙事规范」维度；确定性重复段落检测；AI 润色并入。

## 发布目标与安装提示

- 平台：Windows x64
- 安装包与标签指向同一提交（quick Windows package 工作流会校验并固定 tag 到实际打包的 commit）
- 该 release 不参与应用内自动更新
