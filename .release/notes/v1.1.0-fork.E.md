# AI 小说作家 1.1.0-fork.E

个人 fork 的快速构建版本，用于获取可直接运行的 Windows 安装包。应用内更新仍指向上游仓库，因此本 release 仅作下载用途，不作为应用更新源。

## 本版新增：审稿修稿循环收敛

针对「同一章反复 审稿 → 修稿 → 合并 → 再审稿，问题始终不收敛，每轮都再报出一堆问题」的结构性改进：

1. **跨轮收敛度量（确定性判定，不靠模型）**：
   - 新一轮 AI 审稿会与同草稿最近一份 AI 审稿逐条比对：上一轮严重问题/建议的原文引用归一化后仍在当前正文 → 「未修复」；不在 → 「已修复」。
   - 报告顶部新增收敛摘要（如「与上一轮审稿（r3）收敛情况：已修复 4 项，原文未动 2 项」），未修复项连同原文引用置顶展示；判定依据是「引用原文是否还在」，界面明确标注视为已修复 ≠ 语义已解决。
   - 本轮新发现中与上一轮完全同一条引用（同分类 + 同原文）的条目打「上轮已报」标记——连续两轮都报的同一条，多半是修不掉的硬问题或需要改前文。
2. **审稿修复改为定点补丁，不再整章重写**：
   - 「按确认意见修稿」现在按审稿项逐条产出 `find/replace` 补丁，逐字精确匹配应用；改动范围被机械限定在确认清单覆盖的原文上，不再"修一根刺翻一遍土"。
   - 匹配不到原文的补丁直接跳过并告知数量（生成 X 处 / 应用 Y 处 / 跳过 Z 处），模型不再"顺手"改写别处。
   - 模型输出不符合补丁合同时明确失败并提示原因（含恢复默认模板指引），不静默回退整章重写。
3. **修稿时注入事实上下文**：修复模型现在能看到已定稿前文事实与角色状态（与审稿同一事实源），补丁不得与之矛盾；与本章事实源冲突而无法安全修复的审稿项会被跳过而不是硬改。

**迁移注意**：如果你自定义过「审稿驱动修稿」提示词模板，旧模板要求输出整章正文、不符合新的补丁合同，修稿会明确报错——请在模板管理中把该模板恢复默认。

## 上一版已有（fork.D）

- **修复"合并修订稿后立即审稿/修稿被拒"**：合并后标签页草稿状态同步为 `revised`，无需重开草稿。

## 更早版本

- **fork.C**：`max_tokens` 改为取 `min(模型配置输出能力, 上下文可用空间)`；取消会话级 token 累计预扣，门限只保留次数与截止时间；删除全部按 token 量的门限与统计。
- **fork.B**：审稿分片开关与报告决策对齐；分片键路由；清理失效模板；批量流水线适配。
- **fork.A**：AI 审稿并行分片重构；新增「叙事规范」维度；确定性重复段落检测；AI 润色并入。

## 发布目标与安装提示

- 平台：Windows x64
- 安装包与标签指向同一提交（quick Windows package 工作流会校验并固定 tag 到实际打包的 commit）
- 该 release 不参与应用内自动更新
