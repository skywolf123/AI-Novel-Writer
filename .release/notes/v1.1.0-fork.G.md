# AI 小说作家 1.1.0-fork.G

个人 fork 的快速构建版本，用于获取可直接运行的 Windows 安装包。应用内更新仍指向上游仓库，因此本 release 仅作下载用途，不作为应用更新源。

## 本版新增与修复（针对第6章这类多轮审稿不收敛的场景）

1. **审稿修复恢复「全篇修稿」模式，与定点补丁共存**：
   - 「人工确认修稿清单」里的**总体修稿指导**现在是真的全篇指导：**填写后按确认意见修稿会整章全篇修订**，可以重锚时间线、改写未点名的段落；指导作为最高优先级，勾选的审稿项作为要解决的问题上下文。
   - **留空则走定点补丁模式**（上一版的机制不变）：只逐字替换问题原文，机械保证不改别处。
   - 恢复的是 fork.E 之前的原始整章通道，并补上了它当年缺的东西：**已定稿前文事实与角色状态注入**——整章重写时模型能自查是否制造新的跨章矛盾（fork.D 时期整章重写反复制造时间线新矛盾的根因就在这）。
   - 界面已标注两种模式的边界：指导框 Label 与占位文案写明「填写后按整章全篇修稿」。
2. **蓝图「关键事件」支持一键拆分为节拍**：
   - 章节蓝图页「实质冲突与转折」字段新增 **「AI 拆分节拍」** 按钮（标题行右侧）。
   - 旧蓝图的 keyEvents 是一整段长文，审稿只能把它冻结成一条巨型验收目标，逐项核对必然失败（第6章反复出现的「该目标缺少有效的逐项判断」即此因）。点击按钮后，模型把这段文字**按原意**拆成 2-6 个节拍、每行一个，审稿即可逐项核对。
   - **只改格式不改内容**：原文是唯一输入，明确禁止新增、删除、改写事件或引入原文没有的人物、日期、数值——已写章节不会和新蓝图对不上。
   - 结果只回填编辑框、**不自动保存**；拆分改写的是审稿验收目标的来源，由作者确认后手动保存。失败（合同不符、节拍数越界）会明确报错，不静默回填。
   - 与蓝图生成互斥，不能同时运行。
3. **审稿修复补丁的两条防发散规则**（定点补丁模式）：
   - **连锁同步**：修复改变某个日期、时间、数字、字数、编号或称谓时，必须把该旧值在正文其他位置的逐字出现一并替换——治「补了三个字改成四个字、但『她看了那三个字』没跟着改」这类连锁失配。
   - **插入禁带新事实**：插入的新内容不得引入审稿项未给出的具体日期、时间、编号、数值或人名——治「为解释矛盾而插入『理事会昨天决定受理』、又与第2章冲突」这类新矛盾注入。

## 上一版已有（fork.F）

- 删除「本章目标」里无内容的重复覆盖率横幅；横幅只在本章确实没有可核对目标时出现。

## 更早版本

- **fork.E**：审稿修稿循环收敛（跨轮收敛度量、定点补丁、事实源注入）；自定义过「审稿驱动修稿」模板需恢复默认。
- **fork.D**：修复"合并修订稿后立即审稿/修稿被拒"。
- **fork.C**：`max_tokens` 改为取 `min(模型配置输出能力, 上下文可用空间)`；取消会话级 token 累计预扣；删除全部按 token 量的门限与统计。

## 发布目标与安装提示

- 平台：Windows x64
- 安装包与标签指向同一提交（quick Windows package 工作流会校验并固定 tag 到实际打包的 commit）
- 该 release 不参与应用内自动更新
