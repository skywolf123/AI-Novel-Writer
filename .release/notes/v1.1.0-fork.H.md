# AI 小说作家 1.1.0-fork.H

个人 fork 的快速构建版本，用于获取可直接运行的 Windows 安装包。应用内更新仍指向上游仓库，因此本 release 仅作下载用途，不作为应用更新源。

## 本版修复（fork.G 的缺陷修复，全篇修稿模式必需）

1. **修复「总体修稿指导触发整章修订时输出补丁 JSON」**：
   - fork.G 中全篇修稿模式复用了「审稿驱动修稿」模板，而该模板的输出指令硬编码为补丁 JSON——导致填写总体修稿指导后，模型仍输出 `{"patches":[…]}` 且被当作整章正文存入修订。
   - 现在整章模式改用独立模板 **「审稿全篇修稿」（refine_from_review_whole）**：恢复 fork.E 之前的原始整章合同（直接输出修复后的全文章节内容、纯文本、段落空行分隔），并显式禁止 JSON/补丁输出。
   - 该模板同时注入已定稿前文事实与角色状态，整章修订可自查是否制造跨章矛盾；需要重锚时间线时，以总体修稿指导给出的数值为唯一事实。
   - 定点补丁模式（总体修稿指导留空）不受影响，`refine_from_review` 模板一字未动；合并视图两种模式下都只呈现纯文本正文对照，JSON 从不入库。

## 本版沿用（fork.G）

- 总体修稿指导非空 → 整章全篇修订；留空 → 定点补丁修复。
- 蓝图「关键事件」一键拆分节拍按钮（只改格式不改内容，回填编辑框不自动保存）。
- 定点补丁的两条防发散规则：连锁同步（旧值逐处替换）、插入禁带新事实。

## 更早版本

- **fork.F**：删除「本章目标」无内容的重复覆盖率横幅。
- **fork.E**：审稿修稿循环收敛（跨轮收敛度量、定点补丁、事实源注入）；自定义过「审稿驱动修稿」模板需恢复默认。
- **fork.D**：修复"合并修订稿后立即审稿/修稿被拒"。
- **fork.C**：`max_tokens` 改为取 `min(模型配置输出能力, 上下文可用空间)`；取消会话级 token 累计预扣；删除全部按 token 量的门限与统计。

## 发布目标与安装提示

- 平台：Windows x64
- 安装包与标签指向同一提交（quick Windows package 工作流会校验并固定 tag 到实际打包的 commit）
- 该 release 不参与应用内自动更新
